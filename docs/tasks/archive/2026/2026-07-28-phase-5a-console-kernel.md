# Task: Phase 5a — console kernel and web test harness

## Goal

Every pure function the console needs to compose a legal transaction exists and is exhaustively tested, **before any screen exists**. No components, no routes, no network calls: the rendered console is byte-identical after this slice.

Phase 5 is the console (`docs/product/requirements/ledger.md:45`, `:71-77`). ADR 0006 deliberately pushed real correctness responsibility into it — *"composing it — including balancing the legs — is now the console's job, not the API's"* (`docs/adr/0006-write-endpoint-contract.md:41`). This slice discharges that responsibility in pure, testable modules first, so no later slice inlines money math into a component.

It also installs the `apps/web` test runner, which does not exist today, and reconciles three `docs/development/tech-stack.md` rows that currently contradict the code.

**D4 — the currency allowlist reaches the console through `packages/api`, never hardcoded.** `packages/api` has no currency enum today — `currency: z.string()` at `packages/api/src/contracts/wire.ts:37,54` and `packages/api/src/routers/transactions.ts:180`, with validation delegated to `parseCurrency`. A console *picker* needs an enumerable list, which `packages/core`'s barrel does not export (`packages/core/src/index.ts:29-31` exports only `Currency`, `parseCurrency`, `Money`).

Chosen: add an enumerable list to `packages/core`'s public surface and lift the already-existing `minorUnitExponent` (`packages/core/src/money/currency.ts:43`) into the barrel, then re-export both from a new `packages/api/src/contracts/currencies.ts` consumed as `@fintech-ledger-sandbox/api/contracts/currencies` via the already-declared `"./*": "./src/*.ts"` subpath (`packages/api/package.json:8-10`).

Rejected: adding `@fintech-ledger-sandbox/core` as a direct `apps/web` dependency — it would need an `architecture.md` amendment and an ADR to change the declared `apps/* → packages/api → core` direction, for no gain. Also rejected: hardcoding the ten codes in `apps/web`, which is precisely what ADR 0002 exists to prevent — a guessed exponent of 2 on JPY (exponent 0) or BHD (exponent 3) is a silent 100× or 1000× error, and `docs/adr/0002-money-representation.md:21` requires excess precision be *rejected, never rounded*.

A second implementation would drift from the server's `invalid_amount` boundary and produce a form that accepts what the API rejects. That module imports only `@fintech-ledger-sandbox/core` and `zod` — no Drizzle, no Better Auth — so it bundles into the browser cleanly. Verified before this decision was recorded.

**D6 — `apps/web` adopts `verbatimModuleSyntax` + `noUnusedParameters` now. `noUnusedLocals` moves to 5b; `noUncheckedIndexedAccess` is deferred to the end of Phase 5.** `apps/web/tsconfig.json` does not extend `packages/config/tsconfig.base.json` and is missing all four. `noUncheckedIndexedAccess` is the expensive one (cursor stacks, posting arrays, and paginated lists all index) and enabling it mid-phase would blur every slice's diff with unrelated churn. `routeTree.gen.ts` carries `@ts-nocheck` and is unaffected. ## Design

### Components

| Module | Responsibility |
|---|---|
| `packages/core/src/money/currency.ts` | Adds `CURRENCIES` — the enumerable, ordered, readonly tuple of the ten allowlisted codes, derived from the existing `CURRENCY_MINOR_UNIT_EXPONENTS` object so the two can never disagree. No new currency, no changed exponent. |
| `packages/core/src/index.ts` | Lifts `CURRENCIES` and the existing `minorUnitExponent` into the public barrel. Additive only. |
| `packages/api/src/contracts/currencies.ts` | Re-exports both for `apps/web`, keeping the declared dependency direction intact. |
| `apps/web/src/lib/ledger/amount.ts` | Decimal string ⇄ minor units, and formatting at the correct exponent. Delegates parsing to `parseBoundedAmount`; never uses `Number()` or `parseFloat` (`ADR 0002:28`). |
| `apps/web/src/lib/ledger/postings.ts` | `composeTransfer()` and an N-leg variant, both returning a postings array whose signed minor-unit sum is provably `0n`. Exports `assertBalanced()` as a last-line guard; *calling* it before each send is the obligation of 5d/5e, which own the mutations. Rejects >100 legs client-side (`MAX_POSTINGS`, `packages/api/src/routers/transactions.ts:43`). |
| `apps/web/src/lib/ledger/idempotency.ts` | Mints `crypto.randomUUID()` on an explicit `startOperation(kind)` call and persists it, so a reload resumes under the same key; `newOperation(kind)` is the separate, explicit "this is a different operation" entry point. Keys are capped at 200 chars to match `transactions.ts:173`. |

### Idempotency key persistence

Left unspecified this is a correctness bug, not a detail — the storage choice decides whether a reload replays or double-posts.

- **`sessionStorage`, not `localStorage`.** A key must survive a reload and an in-tab navigation, and must *not* outlive the tab. A `localStorage` key leaks a stale in-flight operation into a session days later, where "resume" would replay against an org the user may have since switched away from.
- **Keyed by operation kind**, one slot per concurrent operation kind (`transfer`, `reverse:<transactionId>`, `sandbox-run`, `sandbox-reset`) — not a single global slot, which two open forms would clobber.
- **Cleared on success and on a terminal `409 idempotency_conflict`**, never on a retryable failure. `422 insufficient_funds` deliberately keeps the key so the user can fix the amount and resubmit under it (`docs/adr/0004-idempotency.md`).
- Storage is accessed through a small injectable seam so tests drive it without a DOM.
| `apps/web/src/lib/ledger/errors.ts` | Extracts `data.reason` and maps it to user copy for exactly the 17 published literals plus the three no-reason branches. |

### Happy path

The sequence these modules exist to make correct. 5a delivers steps 2–5 and 8; the surrounding steps are named so the seams are fixed now rather than negotiated later.

1. *(5d)* An admin opens the transfer form and picks a source account, a destination account, and types an amount as a decimal string.
2. `startOperation("transfer")` mints and persists an idempotency key. This happens **on form open**, not on submit and not during render — so every subsequent retry of this same intent reuses one key.
3. `parseAmount(decimal, currency)` converts the string to `bigint` minor units at that currency's exponent, or returns a typed rejection. No `Number()`, no `parseFloat` (`docs/adr/0002-money-representation.md:28`).
4. `composeTransfer({ source, destination, minorUnits, currency })` returns a two-element postings array: a debit on one account and a credit on the other, in the orientation pinned by the `funding` fixture.
5. `assertBalanced(postings)` confirms the signed minor-unit sum is exactly `0n` and the leg count is within 2..100.
6. *(5d)* The array plus the persisted key go to `transactions.create`.
7. *(5d)* On success, the key's slot is cleared and the user lands on transaction detail.
8. On failure, `describeFailure(error)` turns `data.reason` into user copy. A retryable rejection leaves the key in place so resubmission is a replay, not a second posting; `409 idempotency_conflict` clears it and requires explicit intent to start over.

### The 17 published reasons

Verified exhaustively against `packages/api/src` — the console must switch on `data.reason` and **never** on `message` (`docs/backend/error-handling.md:17-18`):

`account_inactive`, `account_name_taken`, `account_not_found`, `currency_mismatch`, `idempotency_conflict`, `insufficient_funds`, `insufficient_role`, `invalid_amount`, `invalid_cursor`, `no_active_organization`, `non_positive_amount`, `not_a_member`, `rate_limited`, `too_few_postings`, `transaction_not_found`, `unbalanced_transaction`, `unsupported_currency`.

Plus three branches that carry **no** reason and must still render something honest: a bare `401 "Authentication required."`; an oRPC `BAD_REQUEST` carrying `data.issues` from Zod; and any unmapped 500.

`rate_limited` additionally reads `scope`, `limit`, and `retryAfterSeconds` from the body — there is no `Retry-After` header (`ADR 0007:41`).

`account_not_found` and `transaction_not_found` copy must never imply that the row exists in another tenant (`docs/adr/0005-tenant-isolation.md:32`).

### Why this slice is first

Two of the phase's three worst failure modes are **undetectable by the server**:

1. **A balanced-but-wrong postings array.** An unbalanced array is caught (`422 unbalanced_transaction`), but an array with the right total and an inverted direction, or the wrong account, posts cleanly, moves sandbox money, and produces no error — there is no `data.reason` for it, because from the server's view nothing is wrong.
2. **A re-minted idempotency key on retry.** `ADR 0006:17` — retrying under a fresh key posts the payroll twice. The request hash excludes `idempotencyKey`, `orgId`, and `actorId` (`packages/api/src/contracts/request-hash.ts:34-44`), so nothing upstream dedupes it. The concrete vectors are React 19 StrictMode double-invoke, TanStack Query mutation retry, and minting inside render.

Both live in pure functions. This is the only slice that can be proven exhaustively, and the only one needing neither an organization nor a DOM.

### Folder convention (written into `frontend-architecture.md`)

- `src/routes/**` — thin route definitions only
- `src/features/<domain>/**` — screen-scoped components and hooks
- `src/lib/**` — cross-cutting logic, no JSX
- `src/components/shell/**`, `src/components/states/**` — app-wide chrome

Money math and leg composition live in `src/lib/ledger/**` and are imported by components, never inlined into them (`docs/development/coding-rules.md:55`).

## Acceptance criteria

- `CURRENCIES` is exported from `packages/core`'s barrel and derived from `CURRENCY_MINOR_UNIT_EXPONENTS`; a test asserts the two agree, so adding a currency to one without the other fails.
- `minorUnitExponent` is reachable from `@fintech-ledger-sandbox/api/contracts/currencies` and returns 2/0/3 for the three scales.
- **Table-driven across all ten currencies.** JPY `"12.50"` is rejected (exponent 0) while JPY `"1250"` → `1250n`; BHD `"1.250"` → `1250n`; USD `"12.505"` is rejected as excess precision, **not rounded** (`ADR 0002:21`); `MAX_MINOR_UNITS + 1` is rejected; `""`, `" "`, `"NaN"`, `"Infinity"`, `"1e5"`, `".5"`, `"5."` are each rejected.
- Formatting round-trips: every currency's zero renders at its own scale — USD `0.00`, JPY `0`, BHD `0.000` — and a negative external balance keeps its leading `-`.
- **Orientation test.** Every balance assertion is equally satisfied by a swapped source and destination, so balance alone proves nothing. `composeTransfer` is asserted against a fixture derived from the known-good `funding` scenario in `packages/api/src/sandbox/scenarios.ts` — server-accepted, therefore ground truth — pinning *which* account carries *which* direction. A second case asserts that swapping source and destination produces a **different** array.
- Randomised N-leg splits for N in 2..100 assert the signed minor-unit sum is exactly `0n`; N = 101 is rejected client-side before any request is built.
- A simulated retry of one operation yields a byte-identical idempotency key; `newOperation(kind)` yields a different one; two different kinds held concurrently do not clobber each other's slot; a cleared slot re-mints rather than returning the old key.
- **Minting is explicit, provably.** Importing `idempotency.ts` performs no storage write and mints nothing — a key appears only after an explicit `startOperation`/`newOperation` call. Asserted against the injected storage seam (zero writes on import). The React-render vectors — StrictMode double-invoke and TanStack Query mutation retry — are 5d's tests, since they need a mounted component; this slice's job is to make the module impossible to misuse that way by never minting implicitly.
- A `422`-class rejection leaves the key in its slot; a `409 idempotency_conflict` clears it.
- All 17 reasons have copy; an unrecognised reason returns the fallback rather than rendering `undefined`; the three no-reason branches each produce distinct output; no branch renders the raw server `message`.
- `git diff --stat apps/web/src/routes apps/web/src/components` is **empty** — the running console provably cannot regress in this slice.
- `docs/development/tech-stack.md` forms row reads `@tanstack/react-form`, UI primitives row reads Base UI, and the testing row records the `apps/web` suite and its new libraries.
- `docs/frontend/frontend-architecture.md` no longer contains `{{...}}` placeholders and states the folder convention and the server-state/client-state boundary.
- `docs/open-questions.md` is seeded with the known Phase 5 API gaps: no role-returning procedure; no `replayed` flag on create/reverse; no `Retry-After` header; `transactions.list` returns no amounts; no audit cursor past 200 entries; no `accounts.deactivate`; no `reversedBy` reverse lookup.
- `docs/test-coverage.md` records the new `apps/web` suite and its counts.
